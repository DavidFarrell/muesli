# Native read-only source capability ownership — 2026-09-06

The application creates new meetings directly beneath its existing user Application Support `Muesli/Meetings` directory (`MeetingStartPreparation.swift`, `createMeetingFolder`). AppModel passes no alternate directory and its history scans that same root. Existing backend-folder bookmarks authorize the development backend, not meeting-source access. This implementation therefore asks for the existing Meetings root once during preparation of an app session, before capture or the source-free inference reservation. It does not persist authorization across launches.

The main app snapshots the root's path/device/inode. The native broker receives only the path string and those two identity numbers, then independently requires the application's fixed Meetings path. Its own read-only `NSOpenPanel` URL is its sole authority; no URL or bookmark arrives from the unsandboxed main. The selected URL, canonical path and open directory must match the original identity. The broker retains that original root URL and directory for the session. It has exactly `app-sandbox` and `files.user-selected.read-only`, and contains no Python, model loader, network, command/environment API or temporary filesystem exception.

Each job supplies one direct meeting-child component, its unique ID and an immutable seven-word/56-byte lease record. Native admission rejects path escapes, symbolic children/locks, multiply linked lock files, a replaced root, and any changed directory or lock device/inode. It temporarily obtains shared read-only pins while constructing and validating an options-0 bookmark derived from the original selected URL. Both pins and the child directory descriptor close before the reply. The original main and inference helper remain the authoritative long-lived source-pin owners, so a delayed broker retirement RPC cannot hold the archive/file-close barrier open.

The main forwards the returned bookmark bytes unchanged. Root bookmarks are never sent to the inference helper. A unique job token retains the capability session and immutable lease snapshot before the acquisition RPC is sent. Its required `onRegistered` callback lets the inference owner store the token and replay any already-observed process termination before a source handoff is possible. Acquisition has a fixed two-second caller bound. A timeout or late reply cannot retire that token, infer process death or deliver a cancelled capability. Only matching PID/birth and `NOTE_EXIT | NOTE_EXITSTATUS` evidence from the main's original native observer retires it, exactly once. Retirement callbacks and destruction of their captures occur outside state locks.

`retireAdmission()` rejects new authorization/grants and drains existing tokens without cancelling them. Accepted Quit uses this so a claimed live job can receive its normal `meeting_stop`, including when Quit is subsequently cancelled. `beginShutdown()` is the separate explicit-cancellation path. Broker loss also closes admission and signals each active job once, while original native process observation and main source pins continue. `observeUnavailability` delivers one notification outside locks, including a late registration, so an unavailable original session cannot remain published as Ready. A failed native transport never automatically reconnects for a later retirement RPC.

The broker session uses the original authenticated connection and a public XPC transaction. It has no 62-minute or other job-duration cutoff; a 24-hour live job fits this lifecycle. A normal main owner closes the session after all original job tokens retire. Main connection loss independently terminates the broker without depending on AppKit or file-operation responsiveness. That event is not treated as inference termination. Production retains the original broker through active helpers and cancels on broker loss; it does not rely on receiver authority surviving broker exit. Native helper exit and the original source pins remain required before journal/archive ownership can end.

Apple documents that read-only open-panel authority is selected by the caller's entitlement, that dynamic grants belong to a process, that implicit bookmarks transfer access between processes, and that a directory grant generally covers its hierarchy. The documentation does not explicitly promise that this particular root-to-child conversion attenuates every producer grant or specify the exact producer-exit edge; those conclusions require the bounded runtime evidence rather than assumption. [Apple DTS: On File System Permissions](https://developer.apple.com/forums/thread/678819)

Persistent authorization would be a distinct feature with its own security-scoped bookmark lifecycle and entitlement review. It is absent from this implementation. [Apple: Enabling Security-Scoped Bookmark and URL Access](https://developer.apple.com/library/archive/documentation/Miscellaneous/Reference/EntitlementKeyReference/Chapters/EnablingAppSandbox.html)
