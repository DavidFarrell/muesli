# Manual attachment integrity

New manual attachments receive independent UUID filenames, their original source-session ID, a timestamp in the shared recording timeline, byte count and SHA-256. Equal timestamps and resumed sessions cannot overwrite another attachment. Old entries remain readable without invented source IDs or fingerprints; their original timing scope remains unknown.

Clipboard interaction stays on the UI executor. It transfers encoded image data into the admitted worker; ImageIO inspects dimensions before decoding and normalizing orientation into PNG. Accepted images are at most 16 million pixels, 8192 pixels per edge and 32 MiB encoded; text is at most 1 MiB, matching preview limits. Decoding, file creation, synchronization and manifest transactions run under the same retained meeting-folder owner used by Stop. One active attachment edit is admitted per app; rejected or pending work is visible, and a timeout does not release the original owner.

The worker fresh-reads a bounded, regular, no-follow manifest. Only ENOENT is absence: dangling links and malformed existing lists are preserved. Unique bytes are created with exclusive open relative to a retained directory descriptor, synchronized, then indexed through the recoverable attachments.json transaction. A failed index write can leave an unindexed new file; it cannot overwrite prior bytes or falsely publish a saved attachment. Deletion commits index removal before unlinking the selected saved filename. The retained directory descriptor protects against a path being moved and replaced by a link during a stalled transaction. Old shared filenames remain until their last indexed reference is removed.

UI completion is tied to the original edit, meeting folder and source-session identity. A late save cannot put the old session's attachment list into a new session; a stale pending result cannot override a terminal result or clear a newer rejection. Stop's queued finalizer runs after an already-admitted attachment owner really completes. Unindexed files are retained rather than guessed at by automatic cleanup.

Author validation: 12 attachment regressions plus 15 persistence regressions passed. Cases cover equal-time Resume identities, three transactional write failures, transactional delete failure, legacy shared filenames, actual blocked-UI text and image writes, invalid and oversized image rejection before publication, a blocked attachment owner followed by Stop's retained successor, an attachment-directory replacement during delete, dangling manifest links, corrupt manifests and legacy decoding. Fixtures are synthetic; no clipboard, user attachment or Trash action was used. Independent review and combined UI-preview qualification are separate recorded gates.
