# Archive receipt validation foundation

`ArchiveReceipt` defines schema version 2 for the forthcoming native archive helper. The existing external Merge reference has prose-only version 1. No external contract was changed, no receipt migrated, and no native archive path is enabled by this slice.

The schema uses snake-case JSON keys. It records an operation UUID, canonical source folder plus device/inode identity, complete source file fingerprints and session IDs, output files, required recorded checks, and cleanup state. File fingerprints carry path, byte count and lowercase SHA-256. Source paths are relative; output paths are absolute and outside the source. Native helper inventory must enumerate every original, including unindexed source directories, and omit only the protocol's explicit lock-file set.

Multiple output note groups preserve Merge's existing split-meeting workflow. Every note ID has exactly one raw note, official note and redaction report. The receipt also has one shared speaker-provenance sidecar, reprocessing event log and diagnostic log, plus optional copied attachments. Only the diagnostic log may be empty. Hashing uses bounded memory, rejects symlink components, special files and hard-linked outputs, and verifies opened path identity and file change metadata after reading. The output producer must use actual canonical filesystem paths; Foundation's `resolvingSymlinksInPath()` can retain the `/var` alias on this Mac, so its spelling alone is not proof of canonicalization.

Only `retained` receipts validate. `pending`, `uncertain` and `trashed` require reconciliation, never an automatic blind retry. Changed source identities, extra or missing originals, duplicate paths/session IDs, incomplete split-note groups, incomplete recorded processing checks and changed output hashes fail explicitly. These are checks of recorded handoff evidence, not a claim that booleans prove semantic correctness.

Before this becomes a usable archive helper, a native owner must acquire exclusive `MeetingFileAccess` and all secondary source/artifact/backend/journal leases, validate the actual closed loss-free source inventory, validate processing log/result and deterministic redaction evidence, then call this receipt validator immediately before cleanup. It must reopen the receipt under retained identity, durably publish pending intent outside the source, keep ownership through `FileManager.trashItem`, record the actual returned destination/outcome, and leave ambiguous crash outcomes unresolved. The current pure receipt validator does not acquire those leases, inspect media semantics, update receipts or move files. A successful return is not an archive capability.

Regression fixtures are synthetic. They exercise same-length output corruption, omitted original audio, replaced source identity, source-contained receipts, missing output, symlink and hardlink aliases, FIFO rejection without a blocking read, unknown/previous cleanup outcomes, split-note completeness, failed checks and duplicate processing coverage. No user recordings or actual Trash operation are used.
