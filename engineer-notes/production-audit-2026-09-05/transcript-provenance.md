# Transcript provenance and recoverable replacement

Transcript records retain the original `speaker_id`, `stream`, and optional `source_session_id`. A name is stored against an encoded tuple of all three fields. Legacy bare name keys can name only records without a source ID. Replayed speaker events use the source and stream on each known-speaker entry, and machine labels do not overwrite reviewed names. Partials, overlap replacement, and echo comparisons are restricted to the same source.

The viewer and speaker editor use scoped keys. Speaker identification accepts exact keys and does not infer identity from a numeric label, microphone stream, name uniqueness, or result order. Its scoped prompt treats images without verified source/time association as insufficient evidence for assigning a turn. Proposals still require the existing user review. Raw IDs and source IDs remain in JSONL; text includes source IDs and display names. Batch `transcript_sources.json` preserves even silent source inventory. A later save without complete inventory replaces it with explicit `null`, avoiding stale inventory after resume; capture metadata and source manifests remain authoritative.

`TranscriptReplacement` prepares text, JSONL, source inventory, and meeting metadata before disk mutation. It preserves the prior capture status: inference cannot certify capture completeness. `TranscriptModel.applyReplacement` commits the files before publishing any model changes. A failed Replace keeps the prior UI and pending result, with a Retry saving action.

`TranscriptPersistenceStore` stages verified and synchronized new files and original backups in `.transcript-transaction`. A durable prepared journal precedes changes to canonical files; a committed journal follows their directory synchronization. Failure restores the old snapshot. If restoration also fails, it throws an explicit recovery error and retains the journal and originals. Recovery is idempotent: prepared means restore old, committed means keep new. App metadata and transcript readers recover before loading. External readers must also treat a remaining prepared journal as unresolved and must not consume a mixture of canonical files. This is a recoverable multi-file transaction, not simultaneous visibility to unrelated external readers during replacement.

The shared finalizer API is `TranscriptReplacement.files(segments:text:metadata:sources:)` followed by `TranscriptPersistenceStore.shared.commit(files:in:)`; encoding and persistence both throw. The root finalizer integration owns adoption and must not mark completion after a failure. This slice leaves its overlapping legacy save call site for that integration.

Validation uses synthetic records only: two resumed sessions with reused/permuted labels; separate stream identities; legacy-name isolation; partial/echo boundaries; source-bearing speaker events; disk staging, metadata replacement, late replacement and journal failure; rollback failure followed by recovery; successful persisted inventory with a silent source; invalid timestamp rejection before mutation. Full Swift suite: 213 tests passed. Release app build passed. No capture hardware or model service was exercised.
