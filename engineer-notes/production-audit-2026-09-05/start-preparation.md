# Bounded meeting storage preparation

`MeetingStartPreparationOwner` owns one immutable fresh/resume attempt. `prepare` has an eight-second caller deadline and returns ready, failed, timed out, cancelled, or busy. It does not cancel arbitrary filesystem work. Timeout/cancellation abandons the result handoff; the attempt remains busy until its original worker and real cleanup finish.

Folder selection, exclusive source-directory creation, resume transaction recovery/metadata/verified media extent, transcript/attachment snapshots, source recorder and artifact-store initialization, session indexing, event journal creation and backend log creation all run off MainActor. The per-folder `TranscriptPersistenceStore.Context` owns metadata access across setup, handoff and late cleanup. No independent metadata lock or recovery call runs on the startup UI path.

A ready result is atomically claimed before AppModel can adopt its owners or start native capture. The worker waits for that claim or abandonment while holding the folder reservation. An abandoned worker closes the source and artifact stores through `requestFinish` and one-shot `observeClosed` callbacks. It waits on actual close, not on the return of a timed-out `finish` call. The single admitted worker may remain blocked; retries do not create more workers, waiter tasks or source owners.

A successfully created source remains indexed if later preparation fails. After actual cleanup, its session is interrupted with zero captured duration and an end equal to its preparation start. Earlier session entries and files remain intact, and the prior aggregate status is preserved into the prior session outcome. No native output was admitted for an abandoned preparation, so its unused artifact directory remains on disk without being indexed as an unknown capture interval. Existing orphan audio-session directories are skipped, never reused. Every session gets an exclusive `audio*/backend.log` and `audio*/transcript_events.jsonl`; resume does not truncate prior logs. Resume snapshots have explicit 64 MiB transcript and 4 MiB attachment-manifest limits.

Validation: 241 Swift tests passed, including seven startup controls (blocked first file creation, cancellation after source indexing, late video preparation, setup failure, blocked actual recorder close, successful ownership transfer/resume with exclusive logs, cancellation before admission). A one-shot completion race test covers registration before/after/concurrent completion. The startup owner and its 18 production dependencies pass Swift 6 typechecking with default MainActor isolation. Optimized ad-hoc signed Release build passes.
