# Bounded clock correction observations

This change transports and persists diagnostics; the separate processor/retimer change supplies them. It does not change PCM, timestamps, loss counters or clean-completion policy.

`CapturedClockCorrection` contains generation-local cumulative native, nominal-output and host-output frame counts, observed/uncertain interval counts and optional observed rate extrema. `CapturedMicAudio.clockCorrection` defaults to nil, preserving existing producers. The actual `MicAudioForwarder` reports diagnostics only after its packet-generation/meeting-epoch fence and only when the diagnostic generation also matches. Its production recording writer is the `LocalAudioRecorder` passed by AppModel; no additional sink wrapper exists on this base.

The optional manifest field `clock_corrections` holds at most one summary per mic/system source. Each summary contains cumulative totals including the latest observed generation, an observed-generation count, all-generation rate extrema, the latest full observation and an explicit `counters_saturated` flag. Same-generation updates add counter deltas; duplicate, older-generation and regressing observations cannot inflate or replace the accepted summary. Totals saturate instead of overflowing. The diagnostic serialization bound accepts finite rate ratios from 0.5 through 2; this is deliberately separate from the retimer's tighter supported-drift policy.

Recorder admission uses its existing short state lock. The commit timer and final close barrier copy these fixed-size summaries through the existing synchronized manifest replacement. No per-packet file work is introduced. Close synchronously rejects later diagnostic updates. Summaries describe conversion observations, including uncertainty, and must not be interpreted as committed source counts or missing audio. Existing manifests without this additive field still decode.
