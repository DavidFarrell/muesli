# Saved output evidence (6 September 2026)

This native verifier reads persisted output bytes. It does not authorize a move, certify names/redaction meaning, or assert that a Markdown renderer displayed an image. The final archive owner must separately reacquire exclusive source/secondary ownership, compare the complete prepared inventory with a fresh inventory, validate the actual native completion proof against that source, call this bounded output check and the receipt validator, then journal pending intent before any native Trash call. Native copier construction and that final owner are separate unfinished work.

The processing verifier now carries the exact source UUID set and composite `(source UUID, mic/system stream, speaker ID)` set derived from validated turns. Speaker labels alone are never identity proof.

Provenance schema 1 has exactly `schema_version`, `operation_id`, `notes`, `speaker_claims`, and `images`. Duplicate raw JSON keys and unknown/missing fields are refused. Notes have exactly `note_id` and `source_session_ids`, cover each receipt note group once, and collectively declare every processed source. Claims have exactly `source_session_id`, `stream`, `speaker_id`, `name`, `basis`, `evidence`, and `uncertainty`, and cover the native composite speaker inventory once. Basis is always `inferred`; uncertainty must be nonempty. A non-null name requires nonempty evidence. These are recorded declarations, not semantic truth.

Each image declaration has exactly `note_id`, `variant` (`raw`/`official`), `source_session_id`, `asset_id`, and `vault_path`. Canonical copied paths are `MuesliAssets/<lowercase source UUID>/<lowercase asset UUID>.png`. Saved note bytes must contain exactly the declared `![[...]]` embed paths for their variant, without duplicates. Unknown images, other image/embed syntax, HTML, escapes, aliases, fragments, and URL image references require review. The scanner checks saved byte references; it does not infer renderer behavior. Raw and official copies can live in different folders under the same vault. All receipt attachments must exactly match referenced native copy observations and actual saved file fingerprints. Native copy observations must independently bind ledger identity/time, original bytes and copied destination; nothing in this sidecar supplies that authority.

Every raw/official pair is read from actual files and checked by complete ByteEditEvidence replay. The actual saved event log must match the native completed process's byte count/hash. Reads use the existing no-symlink, single-link, descriptor-validated receipt reader. The broader receipt scan must follow this preflight, so untrusted lengths cannot bypass aggregate bounds.

Bounds: at most 256 note groups, 4096 claims/images/outputs, 2 MiB provenance, 8 MiB per note, 16 MiB per edit report/diagnostics, 64 MiB processing log, 128 MiB per copied image; 128 MiB aggregate semantic reads and 512 MiB aggregate output bytes. Over-budget or unsupported cases retain the original for explicit review.
