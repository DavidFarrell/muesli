# Durable archive move journal

`ArchiveMoveJournal` records move intent and observed outcome outside the original source. It does not move files or authorize cleanup. The future native owner must first verify the source, processing and saved outputs, then retain all owners and this journal through actual move completion.

The caller supplies an existing canonical app-owned directory with mode0700 and exclusive `MeetingFileAccess`. Descriptor-relative opens reject symlink traversal, changed ancestors, nonprivate ownership files, hardlinks and special files. A root-level actual flock serializes journal writers. Source ancestry is rejected before any ownership-file creation, so an invalid journal path cannot mutate originals. The journal itself retains exclusive source ownership until actual deallocation.

A source-specific immutable initial anchor and mutable outcome marker are created with O_EXCL and mode0600. Both files and the parent directory must pass fsync plus macOS F_FULLFSYNC before the initializer returns. The anchor is never renamed or deleted. An existing anchor blocks a new initializer even if the mutable marker has disappeared; absence cannot turn a failed terminal publication into a retry opportunity. Unsupported/failed full synchronization returns no pending capability and permits no move. Any partial marker remains for reconciliation. An existing marker of any type or phase blocks automatic reuse; source inode reuse is deliberately conservative. Record size is bounded to256KiB, source UUIDs128, path lengths16KiB, receipt size8MiB and diagnostic codes128 ASCII bytes.

Terminal state uses a newly created private file, synchronization, atomic RENAME_SWAP and directory synchronization under retained path identities. The displaced marker remains at the staging name and must match the original retained descriptor and exact bytes before success can be reported. A marker substitution or in-place mutation is rejected; both exchanged files are preserved, with no rollback over a concurrent write and no deletion. A second original-marker and anchor check follows directory synchronization. Only one terminal publication attempt is allowed per owner: a failed write cannot generate unbounded staging files by retries. If publishing or syncing fails, the caller cannot claim a durable result; original pending or newly visible terminal state both remain nonretryable. Temporary staging evidence is retained, never broadly deleted during recovery.

`recordMoved` accepts only the path returned by the future actual native move, requires the original pathname to be absent, and verifies that the returned directory has the original device/inode. A changed/missing/wrong/cross-volume destination remains unresolved. This checks physical move identity; it does not independently prove that a directory is Finder Trash. The future owner must call FileManager's Trash API and supply its actual returned destination. Failed/ambiguous native moves produce explicit uncertain state. Neither pending nor uncertain is translated into a blind retry. Read-only inspection does not create files and reports recorded evidence, not a new cleanup authorization.

The original twelve native tests and six correction regressions use only private temporary fixtures. They cover actual fixture rename and original-byte survival, pending/uncertain reuse refusal, initial and terminal synchronization/publication failures, retained source ownership, no-move/wrong-destination rejection, changed root and marker paths, private-root enforcement and side-effect-free inspection. These are deterministic interruption/failure tests, not a claim of physical power-loss qualification or actual Finder Trash execution. Independent Astra review, identified Release and final move-owner integration remain required.

Read-only inspection now requires the immutable pending anchor and binds the visible outcome to its operation, source, sessions and receipt. Missing, partial or inconsistent anchors refuse inspection and reuse. A visible terminal record after an interrupted/failed exchange is reconciliation evidence, not proof that the publishing caller received durable success, and never permission to repeat a move. Older unanchored journal records are retained for explicit reconciliation.

The independently failing marker-substitution test is preserved verbatim. Additional cases mutate at the actual atomic-exchange boundary, change bytes in the same inode, remove the mutable marker, retain an anchor after initial failure, and alter the anchor itself. All unexpected bytes remain on disk; the original owner stays pending on any failed publication.
