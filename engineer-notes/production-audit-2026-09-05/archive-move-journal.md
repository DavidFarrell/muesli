# Durable archive move journal

`ArchiveMoveJournal` records move intent and observed outcome outside the original source. It does not move files or authorize cleanup. The future native owner must first verify the source, processing and saved outputs, then retain all owners and this journal through actual move completion.

The caller supplies an existing canonical app-owned directory with mode0700 and exclusive `MeetingFileAccess`. Descriptor-relative opens reject symlink traversal, changed ancestors, nonprivate ownership files, hardlinks and special files. A root-level actual flock serializes journal writers. Source ancestry is rejected before any ownership-file creation, so an invalid journal path cannot mutate originals. The journal itself retains exclusive source ownership until actual deallocation.

A source-specific marker is created with O_EXCL and mode0600. File and directory fsync plus macOS F_FULLFSYNC must succeed before the initializer returns. Unsupported/failed full synchronization returns no pending capability and permits no move. Any partial marker remains for reconciliation. An existing marker of any type or phase blocks automatic reuse; source inode reuse is deliberately conservative. Record size is bounded to256KiB, source UUIDs128, path lengths16KiB, receipt size8MiB and diagnostic codes128 ASCII bytes.

Terminal state uses a newly created private file, synchronization, atomic rename and directory synchronization under retained path identities. Only one terminal publication attempt is allowed per owner: a failed write cannot generate unbounded staging files by retries. If publishing or syncing fails, the caller cannot claim a durable result; original pending or newly visible terminal state both remain nonretryable. Temporary staging evidence is retained, never broadly deleted during recovery.

`recordMoved` accepts only the path returned by the future actual native move, requires the original pathname to be absent, and verifies that the returned directory has the original device/inode. A changed/missing/wrong/cross-volume destination remains unresolved. This checks physical move identity; it does not independently prove that a directory is Finder Trash. The future owner must call FileManager's Trash API and supply its actual returned destination. Failed/ambiguous native moves produce explicit uncertain state. Neither pending nor uncertain is translated into a blind retry. Read-only inspection does not create files and reports recorded evidence, not a new cleanup authorization.

Twelve native tests passed using only private temporary fixtures. They cover actual fixture rename and original-byte survival, pending/uncertain reuse refusal, initial and terminal synchronization/publication failures, retained source ownership, no-move/wrong-destination rejection, changed root and marker paths, private-root enforcement and side-effect-free inspection. These are deterministic interruption/failure tests, not a claim of physical power-loss qualification or actual Finder Trash execution. Independent Astra review, identified Release and final move-owner integration remain required.
