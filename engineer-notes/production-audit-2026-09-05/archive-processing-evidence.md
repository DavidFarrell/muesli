# Native processing evidence gate

This is an internal validation boundary, not an enabled archive command. It establishes recorded source-to-model byte coverage and observed protocol completion; it does not establish transcription accuracy, speaker identity, sensible note splitting or semantic redaction. No process launch, output mutation or Trash operation is added.

`ArchiveProcessingEvidence.validate` accepts bounded complete JSONL, an exit code supplied by the actual process owner, and independent source expectations. It refuses nonzero exit, error/unknown/noise events, partial tails, duplicate or escaped-alias JSON keys, missing/duplicate final results, post-result events and unsupported schemas. Explicit wire keys avoid automatic snake-case decoder aliases. Structural parsing is bounded to 48 levels and 200,000 nodes per record; the journal is limited to 64 MiB, 100,000 records and 4 MiB per record.

Automatic archive eligibility requires every source and both streams, exact source UUID/path/offset/extent, closed manifest fingerprint/revision, full committed PCM fingerprint, canonical normalized WAV bytes, consistent turn and speaker inventories, and enabled successful recovery. A proven zero-byte stream may be empty. Nonempty audio with no turns remains for review; this code does not infer silence. Partial recovery failure remains useful transcription output but is insufficient to discard originals.

Recovery windows must identify the exact rounded frame range, corresponding canonical WAV format/size/hash and consistent complete counters. The native caller must independently derive that hash from retained original PCM; a missing callback or report-only hash is insufficient. At most 1,024 windows and 16 GiB of aggregate full-source rehash reads are admitted, with budget reserved before each callback. Beyond the conservative limit, originals remain for review.

`ArchiveSourceEligibility.VerifiedSource.verifyProcessing` builds expectations from its independently inspected inventory and derives each recovery hash from original PCM under retained exclusive/source leases and descriptor-relative path checks. Hashing a range also rehashes the entire original PCM, so edits outside the selected range invalidate it. It produces no temporary audio. This retains source ownership through the call. The future archive owner must still revalidate the complete source/output inventory immediately before cleanup and obtain the exit code from its own completed process; a receipt assertion is not a substitute.

Validation: 39 focused native tests passed, including both processing policy and real temporary source ownership. Regressions cover missing/duplicate streams, changed manifest/PCM/model evidence, unsuccessful/no-turn processing, contradictory counts/timing/speakers, absent/wrong recovery-range verification, altered range length, duplicate/escaped wire keys, oversized/incomplete journals, changed original PCM outside a selected range, and replaced source ancestors. No client recordings were used. A separate pre-freeze Swift interoperability probe accepted the actual Python producer's synthetic two-stream fixture with expected hashes independently derived from its original PCM and manifest; frozen producer integration and independent native review remain required.

Independent review reproduced impossible successful word counts at `512fb6a`: a turn with zero main/recovered words and a recovery window retaining more words than ASR returned. The correction enforces turn count no greater than main plus recovered words, each recovery retained count no greater than its ASR count, and the producer's cumulative million-word recovery limit. Zero diarization segments remains legal for unknown-speaker fallback. New positive coverage preserves recovery-only transcript turns. Reviewer rerun remains pending.
