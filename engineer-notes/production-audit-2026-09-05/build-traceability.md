# Build and observed runtime identity

The Xcode app contains `build-identity.json` and the same JSON as an immutable generated Swift constant. Reading `BuildIdentity.current` decodes that constant; it does not wait for filesystem access on MainActor. A build ID is SHA-256 over the canonical identity before adding the ID itself. It changes with the commit, dirty source bytes, expected inputs or recorded effective build configuration. It is a build-input identifier, not a hash of the signed executable and not a signature attestation.

`scripts/write-build-identity.py` runs before compilation on every build and only replaces changed derived outputs. It records the Git commit, explicit nullable dirty state, source-tree hash, lock/project/uv configuration/entitlement hashes, declared format revisions and selected effective Xcode settings. Compiler-flag values are hashed because flags can contain private developer paths. Source hashing includes synchronized source/resource roots even when Git ignores a file. Undeclared files and external/directory symlinks cannot qualify as clean distribution input. The Xcode script sandbox is disabled for this trusted generator because linked worktree Git metadata lies outside SRCROOT; the script writes only its declared derived output files.

Ordinary Debug and Release builds permit dirty input and exported non-Git source, preserving explicit unknown Git fields for the latter. Archive (`ACTION=install`) and `MUESLI_REQUIRE_IDENTIFIED_BUILD=YES` fail if source is dirty or unknown, or a required expected input is missing. This gate does not replace signed distribution, licensing, runtime packaging or capture qualification. The format revisions in `scripts/build-schemas.json` describe current formats, including formats that have no on-disk version key; update them when changing their contract.

New meetings store the originating build identity; each new source session stores its own build identity and source UUID. Resume preserves the originating meeting and old session identities, including unknown legacy identities. Older metadata decodes these optional fields as unknown. Existing transaction owners perform all writes.

`runtime_identity` is a separate, source-scoped durable stdout event. It reports `process_preflight`: observed interpreter version/executable bytes, backend source bytes, allowlisted installed package versions and available VCS commit metadata, selected FFmpeg/shared-Python bytes, and selected local ASR/Senko asset hashes. It never substitutes the app's expected lock for installed evidence. Missing observations stay null/empty/unavailable. ASR uses the exact local directory observed, instead of resolving a mutable model name a second time. The observation is not proof of loaded weights or a guarantee that mutable external files cannot change after observation. The separately packaged immutable runtime closes that latter distribution boundary.

The stopped-session transaction extracts the matching identity only from the journal reader's acknowledged byte range; losing the UI event cannot lose persisted provenance. If the process never reaches the session handshake, the session's observed identity remains unknown. Batch results carry `runtime_identity` separately and save it as `last_reprocess_identity`, preserving capture build/runtime provenance. Unknown fields in a runtime event are not copied into diagnostics. Default Copy Debug exports only the current build, a validated observed-runtime record, numeric counters and sandbox state; it excludes paths, device names, meeting titles/text, source UUIDs, error strings and raw logs.

Validation covers generated JSON/Swift equivalence, deterministic clean identities, dirty and ignored compiler input, missing archive inputs, non-Git exports, compiler overrides without path disclosure, actual selected model bytes, legacy metadata, per-source Resume identity, durable journal tail boundaries and separate batch identity. Full Swift/Python suites and ad-hoc Release are run before review; these do not claim signed or packaged release qualification.
