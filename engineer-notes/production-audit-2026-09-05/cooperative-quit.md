# Cooperative normal Quit

This slice handles normal AppKit termination requests (including Cmd-Q). It does not terminate a real app during tests, intercept SIGKILL, claim crash protection, or install a new app. Existing surviving-child leases remain necessary after unexpected app death.

`ApplicationQuitCoordinator` returns through AppKit's `terminateLater` path. The process can automatically reply YES only after its preparation bridge and every required original owner have finished, with an atomic registry empty-check and admission seal. A five-second timer only opens one nonmodal pending panel. Cancel Quit replies NO and reopens user admission; it does not undo an already accepted Stop. Explicit Quit Anyway warns of unfinished recording/changes and is the only path that can approve exit with remaining owners or reported save failures.

Required tokens cover source-recorder actual final commit/close, video and screenshot actual callback/ledger close, backend factory/native process/stdin/journal/scope cleanup, native recording operations and native system source retirement, transcript-store operations including the queued finalizer, startup preparation and unadopted-ready-result cleanup, backend-log queue close, Stop-to-finalizer dispatch, and accepted coalesced title/name edits across delayed UI callback delivery. Tokens are acquired before asynchronous dispatch; successors are admitted before predecessors release their bridges. Failed waits do not release them. Terminal source/ledger/canonical/log save failures retain bounded diagnostics and require an explicit decision, even when the underlying owner eventually ends. A durably recorded degraded source, such as a power interruption, does not itself mean a pending save.

New user starts, edits, exports, deletes and batch work are refused while quitting. Active live inference keeps the normal meeting-stop/graceful-finalization path; unclaimed inference admissions retire and claimed batch inference cancels through its original cleanup owner. The Start handoff is generation-fenced: a claimed preparation delivered after Quit is closed off UI and persisted interrupted instead of adopted. Cancel Quit cannot restart that older attempt. Preview restarts are suppressed until admission is reopened and existing start/finalization permits them.

Native screen/microphone previews and thumbnail reads are dispensable. Attachment thumbnails use explicit `TranscriptPersistenceStore.Purpose.previewRead`: it refuses an unresolved transaction and its Context cannot commit. This path never runs recovery. It still uses existing ownership/validation and may create empty protocol locks on older folders; it cannot publish a canonical save after the exit seal. Other Store reads remain required because they may recover a journal. Catalog enumeration itself is dispensable; each admitted recovery/migration has a Store token, and later admissions fail once sealed.

Tests use independent registries and production owners with synthetic files/processes. They cover admission-vs-seal, pending-only deadlines, cancelled request generations, explicit failure decisions, real final-manifest stalls, retained queued canonical saves, unadopted preparation cleanup, SDK video completion after timeout, journal preparation and claimed-batch cancellation, native cleanup, backend log closure, coalesced metadata callback handoff, and preview refusal/exemption. No fixture invokes `NSApplication.terminate`, real capture, actual Trash, or hardware sleep.

A hung native or filesystem operation can keep normal Quit pending indefinitely. That is intentional: timeout is not proof of completion. This slice does not promise an exit deadline, semantic transcript completeness, or success of earlier failed saves merely because later operations complete.
