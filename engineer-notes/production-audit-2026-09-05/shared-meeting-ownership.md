# Shared meeting ownership foundation

Two cooperative kernel leases separate archive exclusion from canonical-file transactions. `.meeting-access.lock` is shared while an original file/lifecycle owner is active and exclusive for dedicated archive admission. `.meeting-transaction.lock` is exclusive for each persistence Context. No shared-to-exclusive upgrade is used. Both are regular, single-link, user-owned files opened relative to a retained existing directory with no-follow/close-on-exec flags. Admission rechecks directory and lock identities after locking. Missing/moved folders are never recreated as an admission fallback.

`MeetingFileAccess` is a reference-counted immutable capability with a verified folder URL and Codable directory/lock device/inode identity. There is no public unlock. Acquisition and transaction recovery happen on the existing independent worker, after bounded in-process admission. A deadline/cancelled waiter does not release these objects. The registry hands an accepted terminal successor the same access and transaction objects, with no unlock between operations. Unrelated new operations can fail busy at the kernel boundary; no worker waits indefinitely in flock. File open/close itself is not claimed preemptible.

Start preparation acquires access before prior metadata reads or source-directory creation, and transfers it with Prepared. The original recorder queue and artifact store retain separate references through their real close. AppModel keeps capture access through Stop and passes the immutable reference into the retained finalizer closure, including a finalizer that waits behind another disk owner. Native microphone operations retain access through their real operation/late cleanup; each native system source and its recovery intent retain it through actual stop. Backend admission takes shared access before its factory and secondary backend lease, passes immutable identities to the child launch hook, and retains access through actual process exit, stdin closure and reader cleanup. The separate child-pin correction validates and holds those identities in Python; this document does not claim that unintegrated child work is qualified.

Backend log adoption and close stay on the writer queue. Its access reference survives queued writes and is retired with that handle; an old finalizer addresses its original handle. Catalog/recovery, transcript edits/replacement, export and manual attachments/previews inherit Context access. Speaker identification now takes a bounded owned legacy screenshot snapshot, carrying access into its actual image reads; this changes ownership, not the existing image selection or inferred-name semantics. Ordinary in-app deletion uses dedicated exclusive archive admission and preserves all preexisting source/artifact/backend checks. Tests inject the move; no test calls Trash.

Validation includes twelve new actual subprocess regressions: shared/archive exclusion, independent transaction serialization, rejection before Context mutation, stale directory/lock identity, link rejection, timed-out/cancelled predecessor-to-terminal handoff, abandoned first-file preparation, a source export still closing, a timed-out native operation and its late cleanup, queued log IO/close, a screenshot snapshot outliving its transaction, and a stalled archive callback. Existing startup, persistence, backend, catalog, export and attachment suites are also run. A former backend test is updated to check outer-lock refusal and symlink refusal independently, instead of requiring the old secondary-lock message.

This is a foundation, not permission to archive. The external Merge skill and its closed-app rule are unchanged. Lock files alone cannot establish that an installed older app participates. A later helper must verify protocol participation, validate all source/output/receipt evidence, preserve unindexed or unresolved media, record durable pending/actual outcomes and own the real recoverable Trash operation. No receipt implementation, external instruction update, real recording, model inference, Trash operation or security entitlement change is included here.
