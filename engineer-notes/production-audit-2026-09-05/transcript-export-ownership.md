# Selected transcript export ownership

Export reads the exact selected meeting under `TranscriptPersistenceStore` ownership. That owner performs existing transaction recovery, a fresh bounded metadata read, strict streamed JSONL validation, text rendering with the persisted source-scoped names, and destination I/O off MainActor. It never reads or falls back to the currently displayed transcript model, nor trusts a stale `transcript.txt` companion. JSONL bytes and raw source/speaker identifiers are preserved. Missing, corrupt, oversized or count-inconsistent source records fail visibly. A recording-status meeting must finish saving first; a resumed meeting cannot silently export only its older canonical prefix.

The save panel now names a new ordinary folder containing `transcript.txt` and `transcript.jsonl`. The two files are prepared and synchronized in an exclusively created private sibling directory, then published together using `renameatx_np(RENAME_EXCL)`. Existing destination files, folders and symlinks are never replaced; unsupported exclusive rename fails closed. Destinations inside the selected source tree, including resolved aliases, are rejected. Source files are opened read-only with no-follow regular-file checks. Before publication, failure leaves no final export folder. After publication, a failed parent synchronization reports that the complete folder exists but durability is unconfirmed; it does not report success or remove the published pair. Staging cleanup addresses only explicitly created leaves and an empty directory, never recursively removes unexpected content, and never sweeps historical folders.

`TranscriptExportOwner.start(sourceDirectory:destinationDirectory:onCompletion:)` admits one retained attempt. Its independent wait returns completed, timedOut or cancelled; waiter expiry does not release either the export slot or the selected meeting's folder reservation. Actual completion releases the original owner and supplies a typed result. The UI fences pending and terminal notices by the original attempt ID and displays the actual result outside backend logs, including late success/failure after a timeout. No observer task or repeated retry worker is created.

Memory is bounded by a 4 MiB metadata document and a 4 MiB JSONL record plus fixed read chunks. Output is streamed, so full transcript size does not determine resident memory. Export source and destination filesystem operations may stall; the retained owner reports that pending state and prevents competing attempts while unrelated meeting folders remain usable.

The three old unused synchronous log/transcript setup helpers were removed after confirming they had no callers. The obsolete export encoder/write wrappers are also removed; they previously swallowed failures and allowed mismatched text/JSONL sources.

The focused Xcode suite passes 10 tests. Validation uses synthetic source folders and injectable export checkpoints; no save panel, real user export, recording hardware, or historical-file cleanup is invoked. Cases cover selected-source names/provenance, stale text rejection, stalled source/destination, actual blocked MainActor, cancelled wait and late completion, faults at each publication phase, existing destinations and source aliases, corrupt/missing/oversized/incomplete sources, and recording-state refusal. The native panel appearance and external filesystem behavior remain platform integration checks; the current main app has no App Sandbox entitlement. Future sandboxing must qualify destination authority for sibling staging separately rather than assume the helper's bookmark proof applies.

Primary API contracts: [Apple save panel](https://developer.apple.com/documentation/appkit/nssavepanel), [exclusive rename support](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumesupportsexclusiverenaming).
