# Native processing completion authority

The optional `BatchRediarizer` evidence mode binds a successful batch to the physical folder identity captured by its existing prelaunch source owner. It retains at most 64 MiB of framed UTF-8 events, delivered from the authoritative reader before its lossy interface queue. Framing appends one newline per accepted event, including a complete JSON object delimited by actual pipe EOF; it is an event journal, not a claim to preserve original pipe delimiters.

The non-Codable `CompletedProcessingEvidence` is created only after the actual child exits zero, stdout reaches complete EOF/close without error, and the actual admission resources finish closing. A stalled close beyond the caller's bounded wait throws and retains the underlying owner. Cancellation, nonzero exit, evidence overflow, malformed output or missing native source snapshot cannot return evidence. Evidence collection requires both streams and is opt-in; normal reprocessing does not retain this extra journal.

The proof is deliberately absent from `Result.CodingKeys`. External JSON and saved receipts cannot manufacture it. Its verifier compares the complete prelaunch physical folder/lock identity with a newly acquired exclusive `VerifiedSource`, then invokes the independently reviewed exact source/stream/model-input/recovery validator. Even a byte-identical copy of the same source UUID and manifest cannot reuse the native proof. A completed child is not itself evidence of valid processing: the full verifier must still succeed.

This closes the in-process exit-authority handoff. It does not persist an authority across process restarts, launch an archive command, attest semantic note quality, publish outputs or move originals. The future archive owner must consume the proof in this process, validate saved outputs and freshly revalidate the whole source/output inventory while retaining exclusive ownership through durable pending state and the actual recoverable move.
