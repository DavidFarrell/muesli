# Native archive semantic adapter

This slice consumes native process completion, source eligibility, saved-output evidence, image-copy provenance and the durable move journal. Its original standalone implementation was inactive. The separately reviewed application bridge now wires it into app startup in source; the installed app and external Merge skill remain unchanged and production archive acceptance is still unqualified. All move tests use a private temporary fixture and `FileManager.moveItem`; no test invokes Finder Trash or touches user recordings.

## Native API and trust boundary

`ArchiveSemanticAdapter.Configuration(backendRoot:outputRoot:journalRoot:)` is immutable native configuration. Existing output/journal roots must be canonical, no-follow, user-owned private 0700 directories. Source and vault selections come from the fixed workflow Begin request; neither request nor receipt supplies backend commands, interpreter paths, environment, completion proof or a mover. Production processing always calls `BatchRediarizer.run(stream: .both, collectProcessingEvidence: true)` using the configured backend root. Production moving always calls `FileManager.trashItem` on the verified private staging pathname.

`prepare(_:operationID:)` returns `ArchiveWorkflowOwner<Prepared>.Preparation`. `finalize(_:receiptPath:operationID:)` returns its typed FinalOutcome. The adapter owns detached actual work through return even when its caller is cancelled. The generic workflow supplies the retained shutdown work token and controls disconnect/Quit admission. Prepared has no hidden deinit task: its retained native descriptors require the separately reviewed generic workflow's off-UI disposal owner before activation.

Preparation obtains exclusive source access plus every secondary resource owner, validates closed/loss-free source semantics, and captures every file/directory (including empty directories), file hashes and per-entry device/inode identities. Source sessions are limited to 128 before processing. It safely admits outside-source native roots and the source-specific no-previous-intent gate before native output creation. The native image copier produces its own retained catalog. Only plain source values leave this first scope; every source lease is released before Batch obtains shared access. After actual child/stdout/admission closure, preparation reacquires exclusive source ownership, compares original physical identity before semantic parsing, compares complete inventory, and verifies the native completion proof against independently hashed source/model inputs. It writes synchronized native events, explicit diagnostics and an immutable native manifest, then releases source ownership again. Resume is possible while external notes are being written.

The manifest identifies the exact receipt destination (`<operation>/receipt.json`), native processing-events/diagnostics paths, original inventory, source-scoped speaker tuples and native copied-image catalog. Manifest JSON is informational; the non-Codable native proof remains in Prepared. Diagnostics report native observed closure/verified counts and explicitly say stderr capture is unavailable. They do not claim model semantic completeness or unavailable runtime qualification.

## Output preservation and bounded finalization

Finalize independently reacquires original source EX plus secondary leases, compares physical identity/full inventory, verifies the same actual native process proof and validates the retained catalog. Receipt input is no-follow, single-link, bounded 8 MiB, duplicate-key guarded and bound to the native operation's exact receipt path. Native events/diagnostics must use their original native file records; external note roles cannot rebind native bundle files. The bounded ArchiveOutputEvidence check precedes the broader receipt scan.

Every accepted receipt and output byte sequence is preserved into an exclusively created private validation directory before pending. The snapshot manifest records original and copied paths, role, byte count and hash; the receipt retains per-note identity/provenance. File data and directories receive fsync plus F_FULLFSYNC barriers. The bundle retains bounded plain file identities and directory ownership, reopens one snapshot file at a time and validates bytes/inodes before the move. It does not retain thousands of file descriptors. There are at most two snapshot attempts and 512 MiB cumulative reserved bytes per prepared operation, including failed partial attempts and an 8 MiB manifest reserve. Failed files are retained for review; no automatic sweep or overwrite exists.

Live outputs and the receipt are revalidated immediately before pending, and snapshots/source/copied images are rechecked before and after the actual move. External editors may modify notes after the final live check: this is not a multi-file atomic snapshot. The separately durable, hash-bound native copies preserve the exact accepted version even if a later edit occurs.

## Durable intent and private same-volume staging

A source-specific anchor or marker of any type/outcome is nonretryable. `requireNoPreviousIntent` accepts only exact ENOENT for both names through the existing safe journal-root owner. An unreadable, substituted or missing previous marker is not interpreted as retry permission. The admitted journal directory identity is held across the external note phase, so root replacement cannot make an old intent disappear.

Before any move, a unique 0700 private staging directory is exclusively created beside the source on its actual volume. A retained native staging lock and ancestor descriptors bind that directory. A durable pending journal is created before the first staging rename. Its compatible optional `planned_staging_path` identifies the intended staging destination; `validation_snapshot` hash-binds the exact durable snapshot manifest. Both fields are included in immutable-anchor comparison and every terminal record. Existing records without these fields remain nonretryable.

`renameatx_np(..., RENAME_EXCL)` atomically captures the original pathname into the private staging directory without overwriting an occupant. Both namespaces are synchronized. The native owner verifies that captured directory/lock inode, all file identities/hashes and all directories equal the original inventory. If an ordinary pathname substitution races this rename, the unexpected captured material remains in the recorded private stage; it is never dispatched to Trash and is not rolled back over another pathname occupant. Only a completely matching privately staged source reaches fixed Finder Trash. Returned destination identity and complete bytes are checked, then recorded durably.

Any pending creation attempt, staging/sync ambiguity, move error, missing actual destination or terminal journal failure is uncertain and nonretryable. Only validation failures before any pending creation attempt can return needsCorrection. The adapter also latches running/terminal Prepared use; duplicate finalization cannot create native work. This cooperative protocol does not claim immunity to malicious same-UID modification of private native storage or multi-file atomicity of editor-owned notes.
