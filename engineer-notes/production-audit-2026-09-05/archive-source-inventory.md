# Exhaustive archive source inventory

`ArchiveSourceInventory.capture` runs on the retained file worker under an exclusive `MeetingFileAccess`. Its result retains that same access. It streams hashes for every regular file and returns every directory, including hidden and unindexed entries and empty source directories. It omits nothing, including protocol lock files. A future eligibility validator must inspect these complete inventories rather than treating meeting metadata as an exhaustive directory listing.

The scanner resolves the root's physical spelling with POSIX `realpath`, opens the resolved ancestor chain without symlink traversal, and verifies its device/inode against the already-held exclusive owner before any descendant bytes are read. This handles Foundation shortening `/private/tmp` to `/tmp` without treating an alias as authority. Every descendant is opened relative to its retained parent descriptor, with identity checks before and after use. Directory entries and change metadata are checked again after traversal. Symlink descendants, special files, hard-linked files, changed identities and same-length mutations during reads fail explicitly. All descriptors close on actual return; a waiting caller must not release the original operation on a timeout.

The exact recovery journal path is checked directly through the directory descriptor before and after traversal; any existing type, including case aliases on an insensitive filesystem, or any error other than absence blocks this read-only operation. No transaction recovery is invoked. Limits are 100,000 entries, 32 descendant levels, 16 MiB combined relative-path bytes, 64 GiB per file and 256 GiB total source bytes; exceeding a limit refuses the complete operation, never returns a partial inventory. Hashing uses a fixed 64 KiB buffer.

This is an inventory foundation, not semantic source eligibility or an archive capability. It does not prove that a source completed without loss, that both streams were processed, or that saved notes and screenshots cover the source. The future archive owner must retain the exclusive and secondary leases, validate those facts, compare the freshly captured complete inventory with the receipt, and durably own pending intent through the actual recoverable move. Arbitrary older/noncooperating writers remain outside the lock contract; the external Merge app-closed gate remains in place. No move or external contract is enabled here.

Synthetic regressions cover exact known hashes, hidden files, empty unindexed folders, limits, actual lease retention, recovery refusal (including the actual APFS case alias), special files, same-size mutation, replaced ancestors, added entries, physical root aliases and replacement of the resolved root before any file read. No client recordings or Trash operations are used.
